# NodeGuard روی Windows Server و IIS

IIS گواهی HTTPS را برای سایت NodeGuard مدیریت می‌کند و درخواست‌ها را به Node.js روی loopback می‌فرستد. وظیفهٔ `NodeGuard-control` کنترل‌پلین را هنگام شروع ویندوز با حساب Local Service بالا می‌آورد.

| مورد | مسیر یا نام |
| --- | --- |
| تنظیمات محرمانه | `C:\ProgramData\NodeGuard\config\control.env` |
| فایل موجودی اولیه | `C:\ProgramData\NodeGuard\config\inventory.json` |
| پایگاه دادهٔ SQLite | `C:\ProgramData\NodeGuard\data\control.sqlite` |
| لاگ اجرا | `C:\ProgramData\NodeGuard\logs` |
| وظایف پس‌زمینه | `NodeGuard-health`، `NodeGuard-v2board`، `NodeGuard-dns`، `NodeGuard-telegram` و `NodeGuard-failover` |

موجودی اولیه خالی است. از بخش **سرورها** میزبان‌ها را ثبت کنید. در جزئیات میزبان از **نصب NodeGuard Agent** استفاده کنید. در **نصب و راه‌اندازی** هم می‌توانید با IPv4 و اطلاعات SSH، میزبان را ثبت کنید و Agent را نصب کنید. پنل در اولین اتصال، کلید میزبان را برای تأیید نمایش می‌دهد.

اتصال ادمین V2Board و کلیدهای مدیریت DNS را در **تنظیمات ← یکپارچه‌سازی‌ها** وارد کنید. برای نصب V2bX یک نود V2Board و سرور خارج را انتخاب کنید. پنل پیکربندی را از API می‌گیرد و Agent روی میزبان اتصال موجود را بررسی یا سرویس را نصب می‌کند. صفحهٔ **مدیریت دامنه‌ها** دامنه‌ها و رکوردهای Cloudflare و آروان را نشان می‌دهد.

## تنظیم سرویس‌های اختیاری

برای بازیابی worker تلگرام پس از توقف در زمان نگهداری یا انتشار، اسکریپت `Enable-TelegramWorkerRecovery.ps1` را با دسترسی مدیر اجرا کنید. این اسکریپت از تعریف قبلی وظیفه نسخهٔ پشتیبان می‌گیرد و علاوه بر اجرای هنگام روشن‌شدن ویندوز، هر پنج دقیقه اجرای آن را تضمین می‌کند؛ سیاست `IgnoreNew` مانع اجرای هم‌زمان چند worker می‌شود.

نام متغیرهای محیطی و قالب آن‌ها در [نمونهٔ تنظیمات](../../.env.example) آمده است. پس از تغییر متغیرهای محیطی، کنترل‌پلین را راه‌اندازی مجدد کنید و وظیفهٔ متناظر را در Task Scheduler فعال و اجرا کنید. تنظیمات اعلان و تاریخچهٔ ارسال در بخش **تنظیمات ← اعلان** قرار دارند. اجرای خودکار Failover از رکوردها و اعتبارنامهٔ اختصاصی Cloudflare استفاده می‌کند.

## تغییر رمز ادمین

از «تنظیمات ← امنیت» با وارد کردن رمز فعلی، رمز حساب مدیر را تغییر دهید. پنل هش رمز جدید را در SQLite ذخیره می‌کند و نشست‌های دیگر مدیر را می‌بندد.

برای بازیابی دسترسی از سرور، رمز تازه را با scrypt و نمک تصادفی ۱۶ بایتی به خروجی ۳۲ بایتی تبدیل کنید. مقدار `NODEGUARD_ADMIN_PASSWORD_HASH` در `control.env` قالب `scrypt:<salt-hex>:<digest-hex>` دارد. پس از تغییر مقدار و راه‌اندازی مجدد وظیفهٔ کنترل‌پلین، رمز تنظیم‌شده روی سرور فعال و نشست‌های قبلی باطل می‌شوند.
